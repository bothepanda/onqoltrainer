## Что это и зачем
Тренажёр клинических кейсов для резидентов-хирургов (Казахстан, русский язык). С 25.09.2026 идут **учебные пятницы**: 8 резидентов (2–5 год, включая пользователя), расписание в `Downloads/Resident_Study_Sessions_2026_2027_continuous.docx` (38 пятниц, 29 тем, 9 открытых). Схема: в пятницу N все проходят один и тот же замороженный кейс (обучающий режим, с подсказками), в пятницу N+1 повторяют его **без подсказок** и проходят новый. Система сравнивает попытки (что удержано, потеряно, усвоено). Материалы нужны и для публикации, и как языковой корпус для ONQOL vNext.

## Архитектура (папка `onqol-trainer/`)
- `/` = прежний свободный тренажёр (`src/ONQOLTrainer.jsx`, не менять). `/study` = учебные сессии (`src/study/StudyApp.jsx`), `/study/admin` = панель руководителя (`src/study/AdminPanel.jsx`).
- **Одна** серверная функция `api/study.js` (лимит 12 функций на Hobby; в `vercel.json` rewrite `/api/study/:path*`, `maxDuration` 60 с). Помощники в `api/_lib/`: `db.js` (Neon; локально файл `.data/`), `auth.js` (PIN, токены, админ), `tutor.js` (промпт преподавателя, вызов модели через `@anthropic-ai/sdk`), `grader.js` (оценщик и проверки кодом), `plan.js` (расписание: что открыто в какую дату), `cases.generated.js` (создаётся автоматически из `cases/*.md`, коммитится).
- **Кейсы** = утверждённые markdown-файлы в `onqol-trainer/cases/` (карточка, пациент, ветвления, формуляр, рубрика). `npm run cases` пересобирает модуль; в каждую попытку пишутся версия и хэш кейса. Кейс `fluids-01` сейчас **v1.2, заморожен**; рубрика: 14 пунктов, сумма весов 27; флаги критических ошибок C1 (диуретик до коррекции гиповолемии) и C2 (болюсы при перегрузке).
- Данные: таблицы `residents`, `attempts` (транскрипт jsonb), `gradings` (kind `model`|`human`). ID резидентов R01–R08, тестовые начинаются на **T** (видят все задания, исключены из сравнения); **TH…** = пробный режим, преподаватель на Haiku 4.5.
- Режимы: `tutored` (подсказки трёх уровней, метки `<<HINT item=N level=L>>` пишутся в данные, резидент их не видит) и `retest` (без подсказок).

## Модели, стоимость и подводные камни API
- Преподаватель и оценщик: `claude-sonnet-5` ($2/$10 за 1M токенов). **Sonnet 5 не принимает `temperature`** (400). Размышление включено по умолчанию и делит лимит `max_tokens` с ответом; оценщик поэтому работает с `thinking: disabled`.
- Кэшируются досье (system) и переписка; ≈0,29 $ за попытку, ≈140 $ за 480 попыток (8 резидентов × 60). Лимит расходов в консоли Anthropic пользователь ставит сама (совет: 30 $/мес).
- Функция на Vercel живёт максимум 60 с: таймауты вызовов модели подобраны под это (`timeoutMs`, `retries` в `callModel`).
- Vercel-функция в регионе iad1, а Neon во Франкфурте: возможная оптимизация `regions: ["fra1"]` в `vercel.json` (не сделано).
- Модель нельзя менять посреди исследования без записи: версия модели и промпта хранится в каждой реплике.

## Оценка: как устроена
- **Автооценка выключена по умолчанию** (`STUDY_GRADING=auto` включает её при завершении кейса). Решение пользователя: оценивать **в сессии Claude Code по выгрузке**, это бесплатно в рамках подписки. Разбор для резидента при этом свободный (по улучшенному промпту).
- Правила оценки: 2 = сам, 1 = после подсказки, 0 = нет (в повторе только 0 и 2). Обязательна цитата резидента; код проверяет, что цитата есть в реплике резидента, понижает 2→1 при подсказке по этому пункту раньше цитаты, обнуляет выдуманные цитаты. Пункт 11 (воздержание от действия): 2 только за явный отказ от диуретика или явное «олигурия лечится объёмом», молчание = 0.
- Полный порядок работы и команды: `onqol-trainer/docs/ocenka-po-vygruzke.md`. Правила оценщика: `RULES` в `api/_lib/grader.js` (следовать им дословно).

## Мысли про ONQOL vNext (обсуждено)
Гибрид из трёх слоёв: содержание (клиницист, версионируется) + движок кейса (код: данные и состояния пациента) + язык (модель понимает фразу и озвучивает). В прототипе движка нет, его роль играет промпт, отсюда лишняя выдача данных. Для vNext правило «выдавай только запрошенное» должно быть в коде.
